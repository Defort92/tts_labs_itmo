# Лабораторная работа №1. Нормализация текста

## Цель работы

Подготовить текстовую часть корпуса RUSLAN для обучения синтезатора речи:
выявить записи, которые нельзя читать буквально, безопасно исправить типографику и
сформировать метаданные с сохранённым соответствием между текстом и аудио.

## Принцип решения

Главное ограничение — не нарушить выравнивание текста и аудио. Поэтому обработка
разделена на два компонента:

1. `TextNormalizer` исправляет только те признаки, которые не произносятся:
   пробелы, варианты дефиса и тире, кавычки, повторную пунктуацию, невидимые
   Unicode-символы и форму Unicode NFC.
2. `TextFilter` отклоняет записи, для которых безопасное автоматическое исправление
   невозможно: числа, латиницу, адреса, технические символы, сокращения, инициалы,
   известные аббревиатуры, междометия и текстовые смайлы.

Например, раскрыть `1995 г.` без аудио нельзя: диктор мог сказать «в тысяча
девятьсот девяносто пятом году» или использовать другую форму. Такая запись
исключается, а не переписывается предположительным образом.

## Разведочный анализ

Для воспроизводимого анализа реализован `analyze_ruslan.py`. Он считает строки с
цифрами, латиницей, техническими и именуемыми символами, сокращениями, необычной
пунктуацией, невидимыми символами и смайлами, а также печатает примеры.

Команда запуска из каталога лабораторной работы:

```bash
python analyze_ruslan.py
```

В исходных 22 200 строках обнаружены следующие формальные признаки. Категории
могут пересекаться, поэтому их количества не следует суммировать.

| Категория | Строк | Доля |
|---|---:|---:|
| Цифры | 4 | 0,02% |
| Латинские буквы | 0 | 0,00% |
| Технические символы | 5 | 0,02% |
| Сокращения и инициалы по формальному шаблону | 177 | 0,80% |
| Повторная или необычная пунктуация | 621 | 2,80% |
| Необычные типографские кавычки | 57 | 0,26% |
| Невидимые символы и смайлы | 0 | 0,00% |

Категория сокращений является приближённой: формальный шаблон также находит
одиночные заглавные буквы перед точкой, которые могут быть частью авторского
текста. Поэтому окончательное решение принимает более строгий фильтр после
типографической нормализации.

## Фильтр

Фильтр реализован набором заранее скомпилированных регулярных выражений. Правила
выбраны вместо модели машинного обучения по следующим причинам:

- dev-набор содержит только 300 строк и недостаточен для устойчивого обучения;
- проверяемые признаки имеют явную символьную природу;
- правила интерпретируемы и позволяют объяснить причину удаления записи;
- консервативная фильтрация снижает риск ошибочного соответствия текста аудио.

Позитивный класс — нормализованный текст. Результат на открытом dev-наборе:

| Метрика | Значение |
|---|---:|
| Число примеров | 300 |
| TP | 144 |
| FP | 1 |
| FN | 0 |
| Precision | 0,9931 |
| Recall | 1,0000 |
| F1 | 0,9965 |

Требуемый порог F1 равен 0,90. Единственное расхождение — предложение «Счёт за
прошлый месяц уже сформирован.», отмеченное в dev-наборе как ненормализованное.
В нём нет видимого формального дефекта, поэтому отдельное правило для этой строки
не добавлялось: оно было бы переобучением на ошибочную или неоднозначную метку.

## Нормализатор

Нормализатор выполняет консервативные преобразования:

- приводит строку к Unicode NFC;
- сохраняет регистр, букву `ё` и комбинируемый знак ударения `U+0301`;
- удаляет невидимые форматирующие символы;
- схлопывает повторные пробелы и исправляет пробелы около пунктуации;
- унифицирует дефисы, тире и типографские кавычки;
- исправляет явно ошибочные повторения `!!`, `???`, `..` и `!.`.
- удаляет только непарные кавычки и скобки, не затрагивая корректные пары.

Числа, сокращения и иностранные слова не раскрываются, поскольку это могло бы
изменить реально произнесённую фразу.

## Обработка корпуса

Скрипт `preprocess_ruslan.py` читает двухколоночный исходный файл, применяет
нормализатор, затем фильтр и записывает строки формата:

```text
id|исходный текст|нормализованный текст
```

Скрипт проверяет число входных колонок, сохраняет результат в UTF-8, проверяет NFC
и выводит количества всех, изменённых, сохранённых и отклонённых строк.

```bash
python preprocess_ruslan.py
```

Результат обработки полного корпуса:

| Показатель | Количество |
|---|---:|
| Исходных строк | 22 200 |
| Типографически изменено | 16 067 |
| Исключено фильтром | 100 |
| Сохранено | 22 100 |
| Из них сохранено после проверки аудио | 4 |

Большое число изменённых строк связано прежде всего с завершающими пробелами и
неоднородной типографикой исходных метаданных. Порог сохранения не менее 16 000
фраз выполнен с запасом. Итоговый файл проверен автоматически: каждая строка
содержит ровно три колонки, все строки имеют NFC, дубли идентификаторов и ссылки
на отсутствующие WAV-файлы отсутствуют.

Исходное аудио имело частоту 44 100 Гц. Оно передискретизировано средствами
FFmpeg в монофонический 16-битный PCM с частотой 22 050 Гц. Заголовки всех 22 200
полученных WAV-файлов проверены программно.

## Аудит нормализации и фильтрации

Для проверки результата реализован скрипт `audit_lab1.py`. Он независимо сверяет
исходный и итоговый CSV, классифицирует преобразования и выводит примеры по каждой
причине. Категории в следующих таблицах могут пересекаться.

### Что исправил нормализатор

| Преобразование | Строк |
|---|---:|
| Удаление пробелов в начале или конце | 15 495 |
| Унификация тире и дефисов | 6 789 |
| Исправление повторной пунктуации | 673 |
| Схлопывание повторных или специальных пробелов | 65 |
| Унификация кавычек | 57 |
| Исправление пробелов около пунктуации | 36 |
| Удаление непарных скобок или кавычек | 19 |

Примеры безопасных преобразований:

| Исходный фрагмент | Нормализованный фрагмент | Обоснование |
|---|---|---|
| `что‑нибудь придумаю. ` | `что-нибудь придумаю.` | Вариант дефиса и конечный пробел не произносятся |
| `Мой отец – рядовым… ` | `Мой отец — рядовым…` | Унифицировано тире |
| `Белла.  Мы зашли` | `Белла. Мы зашли` | Удалён повторный пробел |
| `„повестью в диалогах”` | `"повестью в диалогах"` | Унифицированы кавычки |
| `шатается по бульварам?..` | `шатается по бульварам?…` | Исправлена комбинация пунктуации |
| `«…Вы пишете` без закрывающей кавычки | `…Вы пишете` | Удалён непарный непроизносимый знак |

### Почему строки исключены

| Причина | Строк |
|---|---:|
| Инициалы и одиночные буквы с точкой | 55 |
| Аббревиатуры без гласных | 31 |
| Известные аббревиатуры | 21 |
| Сокращения | 10 |
| Технические символы | 3 |
| Цифры | 4 |

Например, `Александрову Г. П.` нельзя однозначно сопоставить с произнесёнными
именами, `КПСС` читается по буквам, а форму `прим. автора` диктор мог произнести
как «примечание автора». Цифровые обозначения `ГАЗ-61` и `МИ-6` также нельзя
раскрыть без прослушивания записи.

Первый вариант фильтра удалял 732 строки. Аудит обнаружил два избыточных правила:
любое слово в верхнем регистре считалось аббревиатурой, а непарные кавычки и
скобки приводили к удалению всей строки. Обычные заголовки в верхнем регистре
теперь сохраняются, а непарные непроизносимые знаки исправляет нормализатор.
После изменения восстановлено 628 строк. F1 на dev-наборе осталась равна 0,9965.

### Проверка по аудио

Для ручной проверки был подготовлен файл `audio_review.md`. Прослушивание
подтвердило следующие решения:

- `001257_RUSLAN`: `Г. П.` произнесено «гэ пэ», строка остаётся исключённой;
- `018457_RUSLAN`: `Д. Я. Р.` произнесено «дэ я эр», а следующее `ДЯР` — слитно
  «дяр»; строка остаётся исключённой из-за первой части;
- `000993_RUSLAN` и `001766_RUSLAN`: аббревиатуры произнесены по буквам, строки
  остаются исключёнными;
- `009017_RUSLAN` и `021885_RUSLAN`: цифры произнесены словами, строки остаются
  исключёнными;
- `001028_RUSLAN` и `006729_RUSLAN`: сокращения произнесены буквально, строки
  сохранены без раскрытия сокращений;
- `000880_RUSLAN` и `001024_RUSLAN`: косые черты и звёздочка не произносятся,
  знаки удалены, строки сохранены.

Аудио-проверенные исключения перечислены по ID только в скрипте обработки корпуса.
Они не ослабляют общий `TextFilter` для новых данных и закрытого теста. С учётом
прослушивания сохранено ещё четыре строки, а общее число восстановленных строк по
сравнению с первым вариантом фильтра составило 632.
