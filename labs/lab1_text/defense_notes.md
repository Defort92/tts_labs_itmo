# Краткое объяснение лабораторной работы №1

## Что было сделано

Цель работы — подготовить тексты корпуса RUSLAN для обучения синтезатора речи и
не допустить неправильного соответствия текста аудио.

Корпус содержит 22 200 записей. Аудио было приведено к требуемой частоте 22 050 Гц.
Для обработки текста реализованы два отдельных компонента:

- `TextNormalizer` исправляет непроизносимую типографику: пробелы, варианты тире и
  дефисов, кавычки, повторную пунктуацию, непарные скобки и Unicode NFC;
- `TextFilter` отклоняет текст, который нельзя безопасно прочитать буквально:
  цифры, инициалы, сокращения, аббревиатуры, латиницу и технические символы.

Сначала применяется нормализатор, затем фильтр. Такой порядок позволяет сохранить
строки с исправимыми типографскими ошибками и удалить только неоднозначные записи.

## Почему числа и сокращения не раскрывались автоматически

Главное требование — сохранить соответствие аудио. По записи `1995 г.` нельзя без
прослушивания определить падеж и точную форму, которую произнёс диктор. Ошибочное
раскрытие научило бы акустическую модель неправильному выравниванию. Поэтому такие
строки исключаются, если произношение не было проверено вручную.

## Почему использованы правила, а не обучаемый классификатор

Dev-набор содержит только 300 примеров. Этого мало для устойчивого обучения модели,
но достаточно для проверки явных символьных правил. Регулярные выражения дают
воспроизводимое и объяснимое решение: для каждой отклонённой строки можно вывести
конкретную причину.

## Полученные результаты

- F1 на dev-наборе: 0,9965 при требовании не менее 0,90;
- precision: 0,9931;
- recall: 1,0000;
- исходных строк корпуса: 22 200;
- типографически изменено: 16 067;
- исключено: 100;
- сохранено: 22 100 при требовании не менее 16 000.

Четыре строки были дополнительно проверены по аудио. Для них подтверждено, что
сокращения произнесены буквально либо технические знаки не произносятся. Эти
исключения привязаны одновременно к ID и точному тексту, поэтому не ослабляют
общий фильтр для новых данных.

## Что проверялось

- 7 автоматических тестов;
- три колонки в каждой строке итогового CSV;
- UTF-8 и Unicode NFC;
- отсутствие повторяющихся ID;
- наличие WAV для каждой сохранённой строки;
- частота 22 050 Гц и читаемость всех 22 200 WAV;
- выборочное соответствие нормализованных и отклонённых строк аудио.

## Возможные вопросы

**Почему удалено только 100 строк?**  
Большинство проблем корпуса были типографскими и исправлялись без изменения слов.
Удалялись только строки с неоднозначным произношением.

**Почему не заменялась `ё` на `е` и не менялся регистр?**  
Эти признаки могут использоваться в следующих лабораторных работах при постановке
ударения, транскрипции и предсказании просодии.

**Почему четыре строки проходят в обход фильтра?**  
Их произношение проверено вручную. Исключение срабатывает только для конкретной
пары ID и точного текста; произвольное похожее сокращение по-прежнему отклоняется.

**Что находится в итоговом файле?**  
Три поля с разделителем `|`: ID записи, исходный текст и нормализованный текст.
