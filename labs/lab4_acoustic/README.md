# Лабораторная работа №4. Акустическая модель

## Наша реализация и результаты
## Постановка задачи

Обучить акустическую модель FastSpeech 2 для голоса RUSLAN. Модель получает
последовательность фонем и предсказывает mel-спектрограмму, длительности фонем,
высоту основного тона и энергию. В лабораторной №5 предсказанная
mel-спектрограмма будет преобразована вокодером в WAV.

Обучение находится в
[`lab4_fastspeech2_training.ipynb`](lab4_fastspeech2_training.ipynb), а
независимая итоговая оценка — в
[`lab4_fastspeech2_evaluation.ipynb`](lab4_fastspeech2_evaluation.ipynb).
Разделение сценариев защищает завершённое обучение от случайного повторного
запуска. В обучающем ноутбуке после завершения установлено
`RUN_TRAINING=False`.

## Входные данные и признаки

- `data/RUSLAN/RUSLAN/*.wav` — 22 050 Гц, mono, PCM16;
- `data/lab3_g2p/utterance_phonemes.csv` — последовательности фонем;
- `data/lab3_g2p/phoneme_alignments.csv` — временные границы фонем;
- `sil` используется как обычный входной токен паузы;
- mel-спектрограмма: 80 каналов, FFT 1024, окно 1024, шаг 256;
- `F0` и энергия вычисляются средствами курсового форка Coqui TTS.

Запись с приближённым выравниванием `005321_RUSLAN` исключается. Также
исключаются записи длиннее 15 секунд: это 255 выбросов (около 1,15% корпуса),
включая фрагменты до 50,7 секунды, непрактичные для Transformer-декодировщика на
8 ГБ VRAM. Все исключения сохраняются в `excluded.csv` с причиной. Для остальных
используется MFA-разметка из лабораторной №3.

## Метод

1. Проверить WAV и фонемные последовательности.
2. Один раз создать детерминированное разбиение 90/5/5 с `seed=42`.
3. При повторном запуске загрузить разбиение из кэша и проверить его целостность.
4. Перевести длительности фонем в целое число mel-кадров и создать one-hot
   attention masks для режима FastSpeech 2 без внутреннего aligner.
5. Проверить токенизацию многосимвольных MFA-фонем курсовым форком.
6. Выполнить двухэпоховый smoke test на 128/32 записях.
7. Только после успешного smoke test запустить полное обучение.

Обрезка тишины отключена: фонемные границы лабораторной №3 относятся к полному
WAV, поэтому обрезка изменила бы количество mel-кадров и разрушила длительности.

## Кэширование и защита от утечки

Разбиения сохраняются в `data/lab4_acoustic/splits/` и не попадают в Git.
Функция `create_or_load_splits()` проверяет:

- параметры разбиения и fingerprint исходных данных;
- отсутствие пересечений между train, validation и test;

Если существующий кэш не соответствует данным, выполнение останавливается.
Пересоздание возможно только явно с `force=True` после проверки причины.
Тестовая выборка не передаётся `Trainer` и остаётся закрытой для итоговой оценки.

3. выполняет свободный inference для трёх детерминированно выбранных примеров;
4. сохраняет таблицы и изображения в `results/`.

Полный проход по 1093 test-записям дал общий teacher-forced loss `1.105759`:
`loss_spec=0.968377`, `loss_dur=0.035736`, `loss_pitch=0.050510`,
`loss_energy=0.051136`, средняя ошибка длительности — `3.508833` mel-кадра на

Свободный inference выявил ограничение, которое teacher-forced loss скрывает:
для трёх фиксированных примеров предсказанная длительность составляет только
64,5–81,9% эталонной. Предсказанные спектрограммы также заметно более сглажены и
теряют часть тонкой гармонической структуры. Следовательно, модель усвоила
общий спектральный контур, но склонна ускорять длинные фразы и усреднять детали.
Окончательно воспринимаемое качество можно оценить только после подключения
вокодера и прослушивания в лабораторных №5–6.

## Актуальное задание курса (upstream)

Оригинальный CLI-шаблон из upstream сохранён в
`train_fastspeech2_course.py`. Основной `train_fastspeech2.py` по-прежнему
предоставляет функции, которые используют наши ноутбуки, тесты и модуль
корректирующего обучения; при прямом запуске он делегирует выполнение
upstream-шаблону, поэтому приведённые ниже команды остаются рабочими.

Уже обученный checkpoint не требует повторного обучения после этого merge:
его конфигурация использует совместимые параметры mel (`22050` Гц, FFT/window
`1024`, hop `256`, `80` mel-каналов, `0..8000` Гц, `np.log`, без signal norm и
trim silence), внешние MFA-длительности, а также предикторы pitch и energy.

При этом новый фиксированный протокол оценки нельзя механически применять к
старому checkpoint. Его `data/eval_sentences.csv` использует выданный алфавит
из 56 токенов (`<SIL>` и фонемы без части признаков долготы), тогда как наша
модель обучена на 89 токенах (`sil` и отдельные долгие варианты). Также новое
правило test-разбиения по делимости номера на 5 отличается от сохранённого
детерминированного разбиения 90/5/5: из 120 новых фраз 107 находились в нашем
train, 8 — в validation и только 5 — в test. Поэтому `evaluate.py` сохранён как
upstream-инструмент, но его показатели нельзя представлять как независимую
оценку этого checkpoint. Наша закрытая оценка на 1093 test-записях остаётся
валидной. Точное воспроизведение нового протокола потребовало бы переобучения с
другим разбиением и алфавитом; merge сам по себе этого не требует.

Без нового обучения можно дополнительно сравнить один checkpoint на нашем
закрытом test-разбиении с эталонными MFA-фонемами и с транскрипциями runtime
G2P. Это измерит устойчивость модели к ошибкам G2P, но не заменит требуемое
upstream сравнение двух отдельно обученных моделей; в отчёте это следует
называть inference ablation.

**Цель работы:** Обучение акустической модели FastSpeech2 на подготовленных в работах №1-3 данных и оценка того, что получилось

**Краткое описание:** В рамках настоящей работы необходимо обучить акустическую модель, способную превращать набор фонем в спектрограмму, и применить алгоритм Гриффина-Лима для получения полноценного звука.

**Суть проблемы**: Три предыдущие работы мы занимались различным преобразованием текстовых единиц для упрощения их преобразования в речь; однако само по себе преобразование текстовой единицы в звук является непростым. Графемы и фонемы являются дискретными единцами, в то время как звучащая речь состоит из непрерывно меняющихся и перетекающих друг в друга компонент: каждой фонеме соответствует не только набор спектральных характеристик, но и природа их изменения во времени, связи различных фонем. Каждой фонеме соответствует разная длительность времени, что делает актуальной задачу предсказания длительности произнесения. Кроме того, существуют просодические характеристики фразового уровня, влияющие на все фонемы сразу: темп, громкость, высота голоса, интонационный контур.

Именно FastSpeech2 в качестве референсной модели выбран не случайно. В этой модели есть явное деление на текстовый процессор (по сути, им является агрегированное решение из трёх предыдущих работ), предиктор длительностей, и модель предсказания спектрограммы. Отдельным блоком стоит вокодер -- модель превращения спектрограммы в аудио. В данной работе в качестве вокодера будет использован алгоритм гриффина-лима.


## Перед началом

**Не меняйте аудио-конфигурацию.** В `train_fastspeech2.py` часть значений отличается от значений по умолчанию в coqui, и это не вопрос вкуса: они продиктованы предобученным вокодером работы №5.

| параметр | по умолчанию в coqui | здесь | что будет иначе |
|---|---|---|---|
| `spec_gain` | 20 | **1** | мел в 20 раз крупнее того, что ожидает вокодер |
| `log_func` | `np.log10` | **`np.log`** | вокодер обучен на натуральном логарифме |
| `signal_norm` | `True` | **`False`** | лишняя min-max нормализация |
| `do_trim_silence` | `True` | **`False`** | обрезка меняет число кадров и ломает внешние длительности |
| `mel_fmax` | `None` | **8000** | из карточки модели вокодера |

Соответствие проверено покадровым сравнением мела из coqui и мела из SpeechBrain: совпадение до шестого знака. Любое изменение этих значений даёт звук, который вокодер работы №5 воспроизвести не сможет.

### 3. Обучение модели

Ваша задача -- обучить модель FastSpeech-2, желательно, хорошую.

Для обучения модели потребуется GPU не хуже 1080Ti и солидное время обучения. При обучении с высоким learning_rate (5e-3) модель сходится и начинает порождать человеческую речь с 24-х часов обучения, однако она не может проучиться глубоко и даже может развалиться. Обучение на низком learning rate занимает гораздо больше времени.

Модель FastSpeech-2 предполагает большое количество вариантов архитектуры, которые могут значительно повлиять на качество. Кроме базовых характеристик, таких как размер батча, оптимизатор, скорость обучения, размерности модели; есть также и дополнительные возможности: предсказание контура Частоты основного тона, предсказание энергий, явное указание длительностей фонем.

Предлагается начать с базового варианта с минимумом зависимостей, и попробовать обучить модель с различными вариантами базовых гиперпараметров и входных данных

```bash
cd labs/lab4_acoustic
python train_fastspeech2.py --run-name baseline --lr 1e-3
```

В рамках обязательной проверки сравните два варианта обучения: использовать `gt` фонемы, из исходной разметки, и предсказанные моделью `g2p`; сравните, какой вариант лучше.

Также попробуйте различные гиперпараметры, в первую очередь -- скорость обучения. Скорость обучения `1e-4` -- скорость по умолчанию в coqui, занимает чрезвычайно много времени. `5e-3` позволяет добиться звучащей речи уже через 12 часов, но также высок риск расхождения модели. В качестве старта предлагается взять среднее значение `1e-3`.

Кроме обозначенных параметров можно попробовать поварьировать и прочие параметры модели, однако важно не значительно параметры аудио-процессора: вокодер, который будет использован в работе #5, зависит от параметров обработки аудио.

За чем следить:

- **общий loss** должен убывать, и тут ничего нового;
- **loss предсказателя длительностей** -- отдельная кривая, и она важнее общей, показывает, получается ли модели вообще сопоставить текст и аудио
- **тестовые примеры**, которые тренер синтезирует по ходу обучения. Первые десятки тысяч шагов это шум; появление речеподобного звука -- первый признак, что всё идёт правильно;
- **признаки расхождения**, если вы выбрали `5e-3`: резкий рост loss, обнуление или взрыв градиентов. Лучший чекпоинт к этому моменту уже сохранён -- он и есть результат.

Для визуализации и контроля обучения рекомендуется использовать `tensorboard`: он рисует всю необходимую информацию и даже сохраняет тестовые аудио.

### 4. Озвучьте отложенные предложения и оцените результат

```bash
python evaluate.py --run runs/baseline
```
Ключевой ожидаемый результат -- то, что модель "говорит", но оценить это не так просто. В данном этапе потребуется запустить модель на файлах из тестовой части и послушать, что получилось, а также посчитать общие характеристики полученного аудио и сравнить с живой речью.

Набор `data/eval_sentences.csv` -- **120 предложений из тестовой части** (номер делится на 5, то есть модель их не видела). Набор одинаков у всех, поэтому результаты сравнимы между собой и с настоящей записью. В нём есть все 55 фонем, которые встречаются в тестовой части, а длительности распределены от 0,75 до 8,6 секунды.

Скрипт раскладывает по три файла на каждое предложение:

| | что это |
|---|---|
| `natural/{id}.wav` | настоящая запись |
| `copysynth/{id}.wav` | настоящий мел → Griffin-Lim. **Потолок**: модели здесь нет вообще |
| `model/{id}.wav` | предсказанный мел → Griffin-Lim |


Кроме звука скрипт печатает два числа.

**MCD (Mel Cepstral Distortion)** -- расстояние между двумя мел-кепстрограммами, в децибеллах. Позволяет понять, насколько вообще спектрально близки результаты

**Диапазон мела** -- минимум и максимум значений амплитуды спектрограммы. Позволяет понять, насколько близки синтезированные записи к эталонным по масштабу.

**Результат этапа:** 120 синтезированных предложений, `eval/mcd.csv`, замеры в отчёте

## Дополнительные задачи

**Важное ограничение по ресурсам.** Полноценный запуск занимает достаточно много времени, и более сложные запуски требуют ещё больше времени. Поэтому для экономии можно пользоваться вашими предобученными чекпоинтами, которые уже сошлись, для проверок каких-то более точных.

Делается это достаточно просто:
```
check = torch.load(CHECKPOINT, map_location='cpu')['model']
check.pop('emb.weight')  # если нужно сбросить набор фонем
model.load_state_dict(check, strict=False)
```

### 1. Длительности из разметки MFA вместо внутреннего выравнивателя

Более явное использование длительностей из нашей разметки, вместо неявного обучения внутреннего выравнивателя; Канонический подход из официальной статьи FastSpeech-2.

```bash
python prepare_mfa_durations.py --out ../../data/mfa_durations
python train_fastspeech2.py --run-name mfa_dur --durations ../../data/mfa_durations/manifest.csv
```

Флаг `--durations` отключает внутренний выравниватель. Сравните качество модели, обученной с явным указанием длительностей, с бейзлайном

### 2. Предсказатели высоты тона и энергии

Оригинальная модель FastSpeech2 также включала в себя модули предсказания энергии и ЧОТ. Они требуют дополнительных вычислений для старта обучения (собственно, подсчёта энергии и ЧОТ), и дополнительных модулей во время обучения и инференса модели. Впрочем, это должно увеличить и качество.
